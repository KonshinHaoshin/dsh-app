# v0.7.0

公网 P2P 直连与自动中继回退：

- 先连接 WSS，再并行协商 WebRTC 数据通道；打洞成功后切换 P2P，失败或直连中断时自动回退。
- Android 原生后台服务支持相同传输，锁屏、Doze、暂停 WebView JavaScript 后仍接收任务结束和审批通知。
- 传输切换保持同一个审批所有者及逻辑会话，以消息序号、确认和去重避免重复分派指令；Host 重启后创建新代次，不自动重发旧变更操作。
- 支持大消息分块和有界背压。P2P 使用 DTLS 加密，协商信息使用配对密钥签名；中继仍可读取经中继的内容。
- 连接页显示 P2P 直连 / 中继，后台面板显示直连数量。无需手动切换或重新扫码。

手机端覆盖更新到 v0.7.0；电脑插件安装 `github:KonshinHaoshin/dsh-app-plugin#v0.5.0` 后重启对应 Host。旧电脑插件继续使用 WSS。官方中继及 STUN 已部署，密钥和既有配对保留；自建中继需更新摘要认证及能力透传。

后台功能仍需在「连接 → 后台连接与通知」开启，并允许通知、电池不受限制。P2P 是否成功取决于双方网络，无法打洞时走中继属于正常行为。iOS 尚无签名安装包及原生后台通知。

验证：19 项手机逻辑测试、20 项界面测试、17 项插件测试、16 项中继/协议测试通过。真实 Chromium/Node WebRTC 验证多 MB 消息、信令重连、协商失败及指令等待中的回退（只执行一次）。Android 17 隔离模拟器通过真实公网信令/STUN 建立原生 P2P，锁屏强制 Doze 并暂停 WebView JS，验证任务/审批通知，切断 P2P 后保留通知及审批、手动回复一次。协议测试使用模拟 DSH，不调用模型或执行工具。Pixel 3（Android 12）已从 v0.4.0 覆盖更新并启动；尚未在两个真实异地网络测量打洞成功率。
